# HandOfFate2Access - Claude Code Instructions

HandOfFate2Access makes **Hand of Fate 2** playable by blind users. Speech is the sole interface. If something fails silently, speaks stale data, or omits information, the player has no way to know. A logged failure is actionable; a silent one is invisible.

The architecture is a port of the sibling project `../hand-of-fate-access` (the mod for the original Hand of Fate). Read its `CLAUDE.md` for the full rationale behind the conventions below; this file records what is different for Hand of Fate 2.

## Game & environment

- Engine: **Unity 2017.4.40f1, Mono (legacy .NET 3.5 profile), 32-bit (x86)**. UI toolkit is **NGUI** (UILabel, UISelectable, UISelectableGroup...); input is **InControl** behind `Defiant.InputManager` / `UIInputManager`.
- Loader: **BepInEx 5.4.23.2 (x86)** + Harmony, vendored in `third_party/bepinex/`. `setup-bepinex.ps1` installs it. The entrypoint is BepInEx's default **`Application` .cctor in `UnityEngine.CoreModule.dll`**; it is the one verified on this game (the `MonoBehaviour` entrypoint the original game needed is not required here).
- Game folder: `<steam library>\steamapps\common\Hand of Fate 2`, found from Steam's `libraryfolders.vdf` by `tools/Find-Game.ps1`, or set `HOF2_GAME`. A bare `dotnet build` needs `HOF2_GAME` set (build.ps1 does it).
- Decompiled game source for reference: `HoF2-Decompiled/` (Assembly-CSharp) and `hof2-firstpass/` (both gitignored). Regenerate with `ilspycmd -p --nested-directories -r "<Managed>" -o HoF2-Decompiled "<Managed>\Assembly-CSharp.dll"`. **Look up any game type/method/field here before guessing.**
- Logs: Unity's `%USERPROFILE%\AppData\LocalLow\Defiant Development\Hand of Fate 2\output_log.txt` has every line live (BepInEx's `LogOutput.log` is buffered and lags). Mod lines are prefixed `[HoF2Access]`; every spoken line is logged as `say:` (queued) or `say!` (interrupt).
- Speech: **Tolk (x86)** for the screen reader (Prism ships x64 only). The SAPI shim `native/hofsapi/HofSapi.dll` (x86, vendored from the original mod, `Speech/SapiRenderer` + `Gambit/WordRenderer`) can render words to PCM for panning; nothing uses it since the gambit switched to outcome stingers (the user's call: no synthetic voice in the gambit, sounds only).
- Audio: no FMOD. `Audio/UnityAudioBackend` hosts Core's mixer in Unity's own audio graph via `OnAudioFilterRead` on a persistent 2D `AudioSource` (`ignoreListenerPause`, no spatialization). All placement is decided in Core.
- Unity 2017's old Mono rejects `RegexOptions.Compiled`. Never pass it.
- Game languages: en, fr, de, es, es-lat, ru, ja, ko, it, pt-br, zh, pl (`LanguageManager.CurrentLanguage`). `Strings` falls back to English for a language with no table; es-lat uses the Spanish table.

## Build, deploy, test

- Releasing (repo `gomods1/HandOfFate2Access`): set `<Version>` in `Directory.Build.props`, rename the CHANGELOG's `## Unreleased` to that version, run `release.ps1` (builds, tests, restages the committed `release/payload` and the READMEs, writes `release/HandOfFate2Access-v<version>.zip`), commit, `git tag v<version>` and push the tag. `.github/workflows/release.yml` zips the committed payload (CI cannot build the plugin: it references the game's DLLs) and attaches it and `installer/HandOfFate2AccessibilityInstaller.exe`, with that CHANGELOG section as the notes. `.gitattributes` keeps the payload byte for byte. The installer is game index 7 of the shared Rust installer in `../installer` (`build_installer.bat` for the online exe, which is committed here; `build_offline_hof2.bat <zip> <tag>` for an offline one with the zip built in).
- `setup-bepinex.ps1` once per game install. `build.ps1` builds and deploys to `<game>\BepInEx\plugins\HandOfFate2Access\` (plugin, Core, Tolk, HofSapi, sounds). `test.ps1` runs the offline xUnit suite.
- The playtest harness is `tools/playtest/hof2.py` (`launch`, `deploy`, `keys`, `until`, `shot`, `say`, `log`, `click`). It is DPI aware (the game renders at the monitor's native resolution). Lessons: hold keys ~150 ms or the game misses them; **never steal focus (Alt taps) while the game is loading**, which hangs its loading screen; launch through `steam://rungameid/456670` (a direct exe launch is bounced through Steam and loses its arguments). `tools/playtest/route_tutorial.sh` replays a fresh profile to the first fight.
- When the game window cannot take focus (another window holds the foreground), drive it through the mod's playtest remote: `hof2.py remote button:Select nav:Down button:F3 kill mod:status`. The game keeps running unfocused; `Diagnostics/RemoteControl` replays the commands through `UIInputManager`'s delegates as keyboard input. It is active only while `playtest-remote.enabled` exists in the plugin folder (the harness creates it; `hof2.py remote off` removes it; never ship it). `autoplay.py N --remote` plays that way, ending fights with `kill`. Run it without a `timeout` wrapper (or kill it by command line afterwards): stopping a backgrounded `timeout ... python autoplay.py` leaves the Python process running, and two autoplays fighting over the game look like mod bugs (focus jumping, the player moving on its own).
- F12 (diagnostic) dumps every `UISelection`'s hovered object; F11 dumps the visible labels and sprites under each menu stack's top menu. Every focus change is dumped by `Diagnostics/Inspector` while `Inspector.Enabled`.
- When composing C# that contains backslash escapes, use the Write/Edit tools, not shell heredocs: the shell layers have mangled `\n` more than once.

## Architecture

Same three-project split as the original: `HandOfFate2Access.Core` (engine-agnostic, net35 + netstandard2.0, unit-tested), `HandOfFate2Access` (the BepInEx plugin: adapters and Harmony glue), `HandOfFate2Access.Tests` (net8 xUnit over Core). If code decides what words the player hears, it belongs in Core; if it pulls a value off a game object, it belongs in the plugin.

### Focus (HoF2 differs from the original here)

HoF2 does not use NGUI's `UICamera.selectedObject` for navigation. It has its own layered selection model: `UISelectionManager` holds one `UISelection` per `SelectionCategory` (Main, Menu, Dialogue, Inventory, Navigation) and an `ActiveStack`; each selection has a `HoveredObject` (`UISelectable`). **Hover is focus; `UISelectable.Select` is activation (a click).** `Focus/FocusTracker` polls every frame: the hovered object of the selection on top of `ActiveStack`, falling back to the highest-priority selection hovering anything. Polling catches keyboard, controller, mouse and the game's own default selection without hooking each path.

`Focus/ProxyFactory` maps the focused object to a Core `UIElement`: the selection-blocker placeholder is suppressed; `PageOptionButton` (encounter choices) reads text, utility line and disabled state; cards read through `CardInfoReader`; settings rows (`PauseMenuControl`) read name and value (`SettingsReader`); challenge-map icons and sections, reward tokens, the dice "in hand" target and the reward circle's collect button have their own readers; everything else falls back to the visible labels under the object. A focus with no visible text yet (a label fading in) is retried for 90 frames; an internal object name is never spoken.

`Focus/ValueReader` + the plugin's value poll: a settings row or a die keeps focus while its value changes; the value is re-spoken on change. `Focus/PanelContext` prefixes a panel's static text (the add-on purchase panel, the deck builder's challenge overview, the names of the additional content and mods screens, the mods screen's slot and state text) the first time focus enters it.

Main-menu screens: the additional content list (`Focus/AddonReader`: each pack's title, subtitle and state, which the game shows only as a banner; `Screens/AddonNarration` reads the details panel as the hovered pack changes; `Patches/AddonContentUI_Patches` makes keyboard hover update the panel and Enter reach the Claim/Buy button, as a controller does) and the mods screen (`Focus/ModsReader`: a mod row's title, on/off and warning, its arrow and inspect buttons; `Screens/ModsNarration` reads the inspect panel). `Patches/SliderControl_LateUpdate_Patch` stops a settings slider scrolling every frame an arrow is held (one step per press; held keys repeat at the game's rate). `Patches/UISelectionManager_OnHover_Patch` ignores mouse hovers while the pointer has not moved since the last key input (a resting pointer otherwise steals focus when a list scrolls under it).

`Focus/CardInfoReader` reads a card exactly as the game's info panel would present it: it instantiates the panel's own layout prefab for that card (`CardInfoPanel.GetLayout`, private) into a hidden zero-scale holder, calls the game's `SetCard`, reads the labels and destroys it. Nothing renders and no game state changes. `Card.Flipped == true` means face down; a face-down card reads as "face down card". What a card shows only as icons or models is added as its marks (`CardInfoReader.Marks`: "has a token" / "token won", "has a shard" / "shard won", decided by the game's own `GetTokenAppearance` / `GetShardAppearance` and the info panel's tick), and a card that prints no kind of its own says its type (`CardInfoReader.TypeName`: the game's `SimpleTypeDesc`, the mod's words for encounters and companions, a customisation card's kind and the gender a look or war paint is for; the player's own sigil adds "yours", since encounters ask which amulet is the player's). Map cells add the marks of a face-up top card and the figures (`Spice`s with a model) on them, "a figure blocks the way" when one does; figure ids are logged, never spoken. The Servant challenge's (DLC_00_Shadow) goblins are named by kind from their spice id (Core `UI/MapFigures`: `Goblin_path*` patrols walk a fixed route and face the card they enter next, `Goblin_block` guards step up/down toward the player's row, `Goblin_track` trackers path one step toward the player, `Goblin_generic` stands still; logic read from the `spices` asset bundle). Every goblin moves on the game's travel-end event, so a card it will step onto after the player moves there reads "a goblin moves here next" (setting `GoblinWarnings`, on by default; not in the shadow realm, the `DLC_00_Shadow` blackboard's `night`). A patrol's heading is its rotation matched to the board's grid axes, unknown while it walks; the focused map card's goblin marks are a polled value (`ValueReader`), re-spoken once every goblin stands still. Each goblin's cell and facing are logged on change (`map goblin`).

### Narration

- `Screens/VoiceNarration`: every voiced line (dealer, companions, characters) is read off `Voice.Instance.CurrentClip`'s loaded `VoiceClipTriggers` (its `Subtitle` string link, whole, before the game splits it into timed chunks) once its audio is playing; spoken once, queued. Polled, not hooked on `Subtitle.Show`: the game only draws subtitles when the player turned them on or the text and voice-over languages differ, so an English player with subtitles off heard nothing of the dealer.
- `Screens/EncounterNarration`: the encounter panel's page text (`EncounterPanel.m_pageText`) and announcement line (`m_announcementText`), each edge-detected on its own (`Screens/LabelWatch`).
- `Screens/PromptNarration`: bottom-bar questions with their buttons, and the bar's F1-F3 hotkey buttons when they appear (each not repeated within five minutes).
- `Screens/RewardNarration`: postfix on `CardSetModifierContainer.OnCardSelected` speaks a reward card as it is turned over (its summary: name, type, stats, marks) and pins its full text in the Details buffer (`ReviewController.Pin`) over the game's jump to the next face-down card, until the player next presses an arrow.
- `Screens/ScreenAnnouncer` also reads the end-of-run menu (`EndRunMenu`: death by wounds or starvation, forfeit, failed challenge) by its title and subtitle when it tops the primary stack; the results screen that follows is announced by name. The appearance screen (`CustomisationMenu`, which an encounter can open mid-run) is announced as "Appearance, F3 to finish": the game turns cancel off there and F3 is the only way out.
- Authored line breaks in a label (the two objectives in one label, a card's paragraphs) become a spoken pause: `TextFilter` turns a newline into a comma unless punctuation already ends the line.

### Minigames

- Chance cards (`Gambit/GambitWatcher`): driven by `ChanceCardTask.RunningTask` and its public `OnRevealChances` delegate. Each card has an instrument for the whole gambit, by its starting slot (harp, flute, handpan, music box from the left: `sounds/card_*.wav` from `sounds/cards_batch.json`; past four, an octave up; `Gambit/CardSounds` registers them, falling back to `GambitTones` if a file fails). A reveal with `ReShuffleConsumed` set is the odds being shown: the screen reader says the card count and the outcome tally in the game's words ("4 chance cards: 3 Success, 1 Failure"), then the teaching walk (time held, each card's instrument then its outcome stinger `sounds/outcome_*.wav` from `sounds/outcomes_batch.json`, panned; never a voice); a reveal without it is the player's pick (outcome spoken). Shuffle: the cards take turns (one every `GambitLayout.TurnSeconds`), each panned to its card's real position along the row (the card transforms move; the game gathers them into a pile and spreads them out), a ringing note following its card. All cards turning face down starts it; focus landing on a card ends it. A face-down card under focus reads "Card 2 of 4, left of centre, face down" (never its outcome). The chance card hints setting explains each step as it starts (shown, shuffle, pick). A gambit over prize cards (food, gold: no `ChanceCard`, so no outcome stinger) lists each card from the left with its amount instead of the tally. Cards live in `UI3D.Instance.CardChoice.Container`. A title the game could not resolve (`****`, or a missing key printed as `**guid**`) is never spoken (`UI.Placeholder`); readers fall back to the next readable line.
- Dice (`Minigames/DiceNarration`): postfix on `DiceRollStatus.Show`; a show that only drops the rolls-left count (reroll starting) is skipped. `Patches/DiceRoller_BeginDiceRoll_Patch` throws on keyboard confirm (the game wants a mouse drag release there). The dice in hand read "dice in hand, Enter to throw" (the confirm key named by device: `ProxyFactory.ConfirmKey`, as for the wheel and pendulum prompts), and `PromptNarration` drops the bar there ("Click and hold to grab dice", a mouse instruction, and the same Throw button).

- Wheel (`Minigames/WheelWatcher`) and pendulum (`Minigames/PendulumWatcher`): both read their audio availability once at `Initialize`, so they must be initialised after `AudioEngine.Initialize` (they were silent before). Card names on the wheel go through `CardInfoReader.ShortName` (the "****" placeholder and empty title templates fall back to the card's first readable line).

### Deck builder

Inside a deck, Enter on the centre card adds it (available cards) or takes it out (your deck), through `DeckBuilderMode.TryAddToDeck`; the game explains a card that cannot move only in a hover tooltip (`DeckBuilderTooltipSet`), so `Focus/DeckRules` says it with the card: a deck rule's own failure text (rendered on an inactive copy of the tooltip's label), "deck full", or a pinned deck card; a refused Enter (postfix on `TryAddToDeck`, spoken only right after a key press, since the recommended fill adds through it too) says "Can't add it: ...". Entering a list says its name and the deck's count. The challenge description (`PanelContext`) is spoken once per challenge, not again on returning from the card zoom. Its actions: F3 starts (only once every deck has enough cards, else the game's dialogue says so), F2 fills the decks with the game's recommended cards (keeping or clearing the player's picks), F1 inside a deck shows filters; all in the F4 help.

`Focus/BrowserWatcher`: the card browsers keep focus on an invisible `LayoutController`; the centre card (`CardBrowser.LayoutControllerCard`) is read on focus and re-read when it changes; the active mode's `Source.Count` change is announced. Mode decks (`DeckBuilderDeck` under a `DeckBuilderMode`) read title/description (resolved via `UIStrings`/`GlobalStrings`) and count.

### Keyboard traps fixed by patches

- Challenge map: confirming the section already showing returns to its challenges (`UIChallengeMapMenu_HandleOnButtonSelect_Patch`); confirming a challenge targets the focused one first (`UIChallengeNav_OnTabSelected_Patch`).
- Dice throw (above).
- Challenge map, Campfire section: the game hands the challenge row the selection without hovering its one tab unless a controller is in use, so on a keyboard nothing has focus and no arrow works (`Focus/ChallengeNavRescue` hovers the first tab after a few empty frames).

### Combat

Ported from the original mod (`Combat/`, `Patches/`): attack telegraphs from `CombatUtils.StartMeleeEffect` / `StartRangedEffect` (in HoF2 every character can counter, so `a_blockable` alone decides counter vs dodge; for ranged the game folds Reflect/Defend into it), wall tones off the NavMesh (`UnityEngine.AI`), projectile/mover/zone/beam/chain voices, the enemy locator, recharge chimes, the wall bump (synthesized at walking cadence while the player pushes into a wall; no game sound, footsteps included, is suppressed). `PlayerCamera` lives in `Defiant.Cameras`. Combat objectives are `CombatEncounter.Objectives` (`CombatObjectiveExitTrigger` = reach the exit, `CombatObjectiveCombo` = combo challenge). Legacy traps (`Trap` with `m_trapPhases`) and the newer `Defiant.Traps` (component traps: their `CombatApplicantTrigger`s and manual applicants) are voiced by `Combat/ZoneSonification`. Trap rooms come from encounters such as `CommonTrapEncounter` and "El camino al pueblo de los duendes" (RoadToGoblinTown); to test one, add that card to a challenge's encounter deck in the deck builder. `Combat/ObjectBeacons` pings `ExitTrigger`s, the armed `AICourtTrigger` and collectable `Loot`; the locator key points at them once no enemies are left. `Combat/FinisherBeacons` pings every enemy the prone finisher can take (`sounds/beacon_finish.wav` from `sounds/finish_batch.json`, cadence in Core `Combat/FinisherBeaconComposer`, quicker than the walk-in beacons since an enemy stays down a few seconds); `IsFinishable` is the game's `TargetUtils.FindProneTarget` test without its range and facing cone. `ReadyTarget` is the whole test, as the finisher key's `ConditionProneTarget` asks it (range and cone around the move input, or the facing with the stick at rest), every 0.1 s: that enemy pings `beacon_finish_ready` (the swish plus a glass ding) instead. The locator plays the same two sounds instead of its ping when the nearest enemy is finishable. `Combat/ArmourCues` voices enemy armour (`Protection`: damaged only by Bash hits, whose hit ids contain "flurry"; it absorbs every other blow, breaks at zero, mends or regrows): it subscribes to `Protection`'s static delegates (absorbed, damaged, broken, regen), records in them and plays/speaks from the pump; samples `sounds/armour_*.wav` from `sounds/armour_batch.json`, Core `Combat/ArmourCueComposer`, own `SoundCategory.Armour` and volume setting. Spoken: "Armoured, use Bash, <key>" once per armour per fight, "Armour broken", "Armour restored" (a regen of armour it saw break). The game's input is `Stun`; every player-facing word says Bash (the user's call of 2026-10-21; the game's own cards say Bash). `CombatKeyNames` logs the game's localized label for it (`GlobalStrings.ControlStun`) once, so the tables' translations of Bash can follow the game's.

`Combat/CombatNarration` counts every living enemy, hidden ones included (a burrowed gnome, a submerged kraken), so a gnome swarm no longer chatters with every dive; the locator filters hidden and invulnerable targets itself. It also announces a snare (`PlayerController.IsSnared`: gnomes latching on, a mage's snare) with the live counter key, and "free" when it ends: the snare's 1-damage ticks are not telegraphed strikes, and the game's only cue is a wobbling icon. Every attack cue that plays is logged (`cue attack_block|attack_dodge right= forward=`), like every spoken line; `tools/playtest/earbot.py` fights by reacting only to those lines and `walk.py` drives the game forward with it (measured 2026-10-18: 0-2 hits per fight reacting to the cues, 10 hits and death in 46 s ignoring them).

## Keys the mod adds

- `F4`: help for the current screen (`Help/HelpController`, entries from Core `Help/HelpCatalog`; combat entries name the live bindings via `Help/CombatKeyNames` and list every combat sound). Up/Down/Home/End read it, Enter on a line naming a sound plays it, F4 or Backspace closes. While it is open `UIInputManager.Update` is skipped (`Patches/UIInputManager_Update_Patch`) and the game's pending button press is dropped every frame, so the closing Backspace never also goes back. The main menu announcement names it.
- `Shift+F4`, or the "Accessibility mod" option the mod adds at the bottom of the main menu and the pause menu (`ModMenu/MenuOptionButton`, a clone of one of the list's buttons spliced into its up/down chain): the mod menu (`ModMenu/ModMenuController`, navigation in Core `ModMenu/MenuNavigator`): combat sounds and chance card / minigame sounds (each entry's meaning, Enter plays it: Core `Glossary/GlossaryCatalog`, played by `ModMenu/SoundExamples`), help topics (the `HelpCatalog` lists; a line naming a sound plays it), settings (Left/Right change, a volume plays a sample; Ctrl+Up reads the explanation). Same input handling as the help list; Backspace or pad B goes back. Not opened in a running fight (it says to pause).
- `Ctrl+Up` / `Ctrl+Down`: the current review buffer's next / previous line (up goes forward, the user's call of 2026-10-21); `Ctrl+Left` / `Ctrl+Right`: switch buffers (`Review/ReviewController`, Core `Review/ReviewBuffer` + `ReviewSet`). Buffers: Details (fed by every focus move from `UIElement.Details()`, also by the map cursor and the deck builder's centre card), Events (every `SpeechPipeline.SpeakEvent*` line, newest first, capped at 200; current when a fight starts), Status (resources and equipped items, rebuilt per read).
- Plain arrows on the map choose the card to move to (Enter moves). The game picks among the reachable neighbours by screen position, so Right on the left neighbour jumped diagonally back to the one above; `Maps/MapNavigation` (prefix on `UISelectionManager.OnNavigate`, map only: `MapInput.OnMap` also requires the map's selection to top the `ActiveStack`, since the inventory opens in its own selection and leaves the map's group selected) makes each arrow select the neighbour in that direction from the player's card, and one with nowhere to go says "Can't go left, you can go down, right" (the plugin's edge-repeat check). A card offered as a move is read from the player ("right, face down card, exit": `MapCellElement`'s move direction), without its own paths, which read as keys to press; the survey cursor keeps them.
- `Shift+arrows` (or right stick) on the map: the survey cursor. Each read ends with where the card lies from the player ("2 left, 1 up from you"); a step with no card that way says "No card further left" before re-reading the current one.
- `Shift+.` / `Shift+,` on the map: the survey cursor to the next / previous unvisited card (Core `UI/MapTour`: nearest first by grid steps, ties top to bottom then left to right, wrapping; recomputed per press). Unvisited means visible, not the player's card, and an encounter whose `ActivationCount` is 0 (the game's `Complete` stays false for repeatable cards such as shops). Each read ends "unvisited 2 of 5".
- `/` or `H` or right-stick click: status (health, food, gold, fame, poison).
- `O`: the objectives.
- `C` or left-stick click (in combat): ping the nearest enemy. (L is the game's camera orbit in HoF2.)

While Ctrl, map-Shift or the help list claims the arrows (`Input/KeyClaims`), `Patches/UIInputManager_GetDirection_Patch` returns no direction, so no game listener (selection manager, score table, deck builder bars) moves. InControl key bindings ignore modifiers, so without it Ctrl+Up would also navigate.

**Never name a mouse button when a keyboard key or pad button is bound** (the user's call: blind players do not use the mouse). `Help/CombatKeyNames` orders an action's bindings keyboard, controller, mouse (controller first while a pad is the active device); every announcement that names a key goes through it. The game ships Counter (the mod's earlier texts called it Defend; every spoken line now says Counter, the name the key list uses) on the right mouse button alone, so the combat help tells the player to bind a key when that is still the case.

`Input/CombatKeyDefaults` adds V (attack), B (Counter) and X (Bash, the game's `Stun` input, which breaks blocks and armour) as keyboard defaults while those actions have no keyboard key (the game ships them on mouse buttons alone), and Backspace as a second key for the menus' Cancel beside Tab (the user's call); it never touches a key the player bound. The combat controls tutorial (`Screens/DialogueNarration`) speaks one line per control, each with the key the live binding names, never the mouse button the diagram draws.

**Never remap the game's keys** (the user's call): F1 (inventory / bar button 1), Tab (cancel), I (inspect), F2/F3 stay the game's. Where a game key is not obvious, announce it. Announcements and help name Backspace (the mod's second Cancel key) rather than Tab (the user's call): the inventory says "Inventory, arrows to browse, Backspace to close" and nothing more; a focused inventory slot reads "Weapon slot, currently Soldier's Sword, 2 other items to equip" (`Focus/InventorySlotReader`; the cards' stats are in the details buffer). Its Inspect (F2/I) is never announced: Enter equips directly and the inspect view shows the same panel the details buffer reads.

## Settings

Core `Settings/ModSettings` (each a `Setting`: section, key, spoken name and explanation, toggle or volume 0-100 in steps of 10), stored by `Settings/SettingsStore` in BepInEx's `BepInEx\config\com.handoffate2access.cfg` (bound in `Awake`; menu changes save at once). Every mod sound belongs to a `SoundCategory`; `AudioEngine` scales a voice by the overall volume times its family's on every play and update. Toggles: lock camera and hear from your character (`Patches/PlayerCamera_Patches`: the fight camera's orbit input is ignored, and the game's listener sits on the player instead of 35% toward the camera), spoken lines, resource changes, action keys, chance card hints, goblin warnings.

**Never suppress a game sound** (the user's call): mod cues only add. `Combat/EnemyPresence` (Core `Combat/EnemyPresenceTracker`) adds footsteps for the 3 nearest moving enemies and a double knock when one comes within reach (`sounds/enemy_*.wav` from `sounds/enemy_batch.json`) on top of the game's own footsteps (animation-driven `SurfaceEffects`, the 8 nearest characters, heard from the listener).

Game keys to keep clear of: arrows, Enter/Space (select), Tab (cancel), F1-F3, I (inspect), `[` `]` `-` `=` (paging), 1-9 (encounter options), Esc (pause), Ctrl+M (the game's debug settings UI); in combat WASD, IJKL (camera), E, Left Shift, Q, R, Space, F, Left Ctrl, mouse buttons.

## Speech: focus vs events

Focus echoes and on-demand reads use `SpeakInterrupt` / `SpeakQueued`. Anything the game says on its own (narration, prompts, combat counts and warnings, minigame results, resource changes, screen names) goes through `SpeakEvent` / `SpeakEventInterrupt`, which also records it in the Events buffer. Focus readouts are concise: a card speaks `CardInfoReader.Parts.Summary()` (name, kind, stats; a shop price; the item it replaces) and lists everything in `Details()`. Stats are paired by their widget under the info panel's `Grid` (caption and number in either order).

## Input latency (diagnosed and fixed 2026-10-16)

`Diagnostics/LatencyProbe` (active while `latency-probe.enabled` exists in the plugin folder) logs per key press the frames until the game dispatches it, focus changes and speech, plus frame times and the mod's per-pump cost. Finding: on the dev machine the game ran fullscreen 3840x2160 with VSync on and the display at 16 Hz (it requested 120 Hz), i.e. 62 ms frames; a key takes one frame to reach the game and one more to be spoken (about 125 ms plus the wait for the next frame plus the screen reader). With VSync off (`latency-probe.novsync` experiment) frames were 6 ms and key to speech 13 ms. The mod's own cost is about 1 ms per frame. The 16 Hz was the Windows desktop mode itself (the display offers 16-60 Hz at 4K, not the 120 Hz the game asks for); with the desktop set to 3840x2160 at 60 Hz the game runs at 60 fps and a key is spoken 34 ms after its frame. A player reporting sluggish keys: check the display refresh rate first.

## Conventions

Inherited from the original mod, unchanged: patch non-virtual chokepoints; manual patching through `Patching/HarmonyPatcher` (logs each result); speak only from the pump, never from a hook; all speech through `SpeechPipeline`, all logging through `Log`; never cache game state (live component references are fine); reuse the game's own localized text, and put every mod-authored word in `Core/Localization/StringTable.cs` with a translation in each table; no silent failures (every catch logs); comments describe the current state, not history.
